Logic Explanation

Single Source of Truth: The loot array declared at the top of script.js is the only place loot data lives. Every number on the screen is derived from that array at render time — nothing is stored in the DOM. If the array changes, the screen updates. If you cleared every displayed number but left the array alone, running updateUI() would restore them perfectly because the data was never lost.

Quantity in the Data Model: Each loot item is a plain object literal with three properties: name, value, and quantity. Quantity was added because a single row should be able to represent "5 Health Potions worth $10 each" as one entry ($50 total) rather than five separate entries. The total contribution of each item is value × quantity, and only the currency total — not individual items — is divided among party members.

updateUI() as the Single Render Point: updateUI() is called after every state change: adding loot, removing loot, and changing party size. Inside it, one for loop calculates the grand total (value × quantity per item) while simultaneously building each row in the loot table. The split result is then computed from that same grand total. No calculation logic exists anywhere else — buttons trigger state changes, then hand off to updateUI() to do all the math and rendering.

State Controls Visibility and Availability: The Split Loot button is disabled unless the loot array has at least one item and the party size is a valid integer ≥ 1. The results box is hidden when either condition fails. The "No loot added" message is shown only when the array is empty. All of these are controlled by adding or removing a .hidden CSS class — no inline style manipulation, no direct style property writes in JavaScript.

Guarding State Integrity: Validation runs before any mutation. If the loot name is blank, the value is not a number, the value is negative, or the quantity is less than 1, the item is never pushed into the array. If party size is invalid, recalculation is skipped. Invalid data cannot enter the system and cannot corrupt the displayed totals.
